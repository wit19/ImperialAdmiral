## 10. What the enumeration does NOT cover

- **RR scope**: the pinned enumeration is the CORE expansion only. Hoth tile ids 19..28 NUMERICALLY overlap the RR interior range but are different physical tiles - the crosswalk keys on (expansion, tileID, side) and a bare 'id in 19..36' rule would wrongly ban them (the one error class named in spec 7). The same keying keeps a Core-19 placed in another campaign correctly BANNED (same physical tile).
- **Biome gaps**: no shipped `Halls/Jabba/Imperial/None/Menu` row is signed. Halls (Bespin/Empire) and Jabba-palace tiles are exactly the RR 'Hallen' class the rulebook would need its own interior rules for; `Imperial` appears as the A-side of the core interior tiles themselves; `None` appears on core 38/39 which the RR pins outdoor. Every such row stays AMBIGUOUS until a Thomas signature (the signature slot is `thomas_ruling` in `tools/massive_interior_crosswalk_candidates.json`, mirrored per row in the doc's census table). Runtime consequence until signed: D2 fail-OPEN + one forensic log line per activation.
- **DP-GUID assignment method**: the app itself never maps a Deployment Point to a tile (all runtime logic rides mapSectionOwner); the assignment above is a CENSUS method, not runtime truth. Seam DPs with mixed-status candidates and tileless DPs are counted in section 9 and must be treated as Ambiguous DPs (D2 reading = OPEN + log) by any later hop until authored data is fixed or a signed tie-break rule ships.
- **Sentinel slots**: editor placeholder GUIDs (null GUID and the default-section GUID) in authored pointList/Specific slots carry a card without a tile attribution - 934 sentinel slots seen. Those placements can neither confirm nor deny an indoor placement.
- **Non-tile channels**: reserved threat-buy groups, Active-spot event deploys (deploymentPoint==0), Optional/Random deployments and AddGroupDeployment actions have no authored card x tile pair (or no named card); indoor Massive play through them is a LANDING-LAW / picker-pool question (D3-B, M13c pool rule), never a D6 override.
- **Text audit reach**: EN canonical lane only; the pattern is deliberately conservative (noun+verb proximity) - phrasings without an indoor noun (pure door/level wording) are out by design, and translated lanes can word permits differently.
- **Runtime overlays**: the runtime `deployLedger` origins (M14e) and manual figure moves are live-session facts this file-level census never sees (card law). Measured at this commit there is no runtime keyword add/remove in the shipped app at all (section 1); the custom-lane '\r' divergence is disclosed in section 1.
